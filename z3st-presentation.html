Motivation

Fuel and structural materials
behave as coupled physics

Under irradiation, temperature drives expansion, cracking and creep — while deformation reshapes the gap, conduction and contact. The physics is two-way coupled, non-linear and multi-material.

The gap in the tooling
  • Industrial fuel-performance codes are often closed, 1.5-D, and hard to extend with new constitutive laws.
  • Research needs a transparent 2-D / 3-D / axisymmetric platform where models can be prototyped and shared.
The Z3ST answer

An open, modular finite-element framework built on FEniCSx

Couple heat conduction and solid mechanics in arbitrary geometries under transient power histories — and drop in your own physics.

Design principles
  • Reproducible, diffable YAML inputs — three plain-text files per case.
  • Material laws as runtime Python — no core edits.
  • Easy coupling with external mesoscale & microstructure codes.

Capabilities

What Z3ST does

Solver

Coupled thermo-mechanics

Heat conduction (stationary or transient, backward Euler) staggered with mechanics.

Kinematics

4 regimes, one entry

2-D plane strain, 3-D, axisymmetric and plane stress via a single config key.

Constitutive

Elastic → plastic

Lamé, anisotropic Voigt, Neo-Hookean, J2 plasticity, and custom UFL stress hooks.

Fracture

Phase-field

AT1 / AT2, Miehe & Amor energy splits, irreversibility, hybrid constraint.

Time-dependent

Creep

Implicit Norton + Arrhenius with an exact AD tangent; optional irradiation creep.

Fuel behaviour

Engineering models

Burnup swelling & densification, Fink UO₂ k(T), rim-peaked radial & axial power.

Interfaces

Gap & contact

Fixed / Gas gap conductance and penalty pellet–clad contact (PCMI).

Meso-scale

Cluster dynamics

1-D defect size-distribution: DG1 + upwind flux + SIPG diffusion.

Architecture

One hub, many mixins

Composition root

Spine multiply-inherits 13 mixins

Each physics model is a mixin contributing residuals and state updates over one shared field namespace (u, T, D, porosity, burnup…).

Composition, not inheritance

MeshManager held as Spine.mgr

Gmsh / XDMF readers, PyVista preview and per-tag DOF location live on their own object.

Config

Three YAML files per case

input.yaml + geometry.yaml + boundary_conditions.yaml — reproducible & version-controllable.

Numerics & solver

How the coupling is driven

Coupling

Staggered loop

Fixed-point iteration with Aitken Δ² adaptive relaxation and per-step form caching; optional gap-conductance damping.

Robustness

Adaptive time-stepping

On a stalled step: snapshot state, bisect dt, re-solve as internal sub-steps, roll back on failure — output stays on the original grid.

Steering

Hot-reloadable params

An allow-listed subset of input.yaml (tolerances, relaxation, max_iters) is re-read at the next step boundary — no restart.

State transport

The eigenstrain bus

Stateful per-point fields — swelling, creep, burnup, gaseous swelling — ride a shared bus with snapshot / restore for rollback.

Linear algebra

PETSc backends

MUMPS direct, or GAMG / HYPRE BoomerAMG iterative; MPI via MPI.COMM_WORLD.

Output

Unified writer

VTU per step or single-file XDMF time series; interpolation expressions compiled once at setup. ParaView & PyVista ready.

Getting started

Install & run a case

# FEniCSx comes from Conda, not pip conda env create -f z3st_env.yml conda activate z3st pip install -e . # run any case folder cd cases/verification/mechanics/uniaxial_tension gmsh mesh.geo -3 > log_mesh.md python3 -m z3st > log_z3st.md python3 non-regression.py # or: ./Allrun

  • VTU / XDMF fields → ParaView & PyVista.
  • utils_plot.py radial profiles: T(r), σrr(r).
  • --mesh_plot previews surface tags in PyVista.

Coupling & ecosystem

Talking to other codes

SCIANTIX — fission gas (prototype)

Mesoscale gas behaviour → eigenstrain bus

Z3ST drives SCIANTIX per fuel point for gaseous swelling & fission-gas release, wrapping its existing C-linkage entry — no SCIANTIX physics is re-implemented in Python.

  • Reuses SCIANTIX's TRANSURANUS-style coupling shim (-DCOUPLING_TU).
  • Host owns burnup (RADAR) and feeds it in; swelling rides the eigenstrain bus.
  • Validated end-to-end vs the SCIANTIX Baker 1977 gold — see next slide.
FEniCSx ecosystem
  • dolfinx_mpc — multi-point constraints (planned).
  • dolfinx_materials — standard material libraries (planned).
  • Neural-network material laws via dolfinx-external-operator.
Multi-scale pipeline (envisaged)
  • Mérope — synthetic microstructure generation.
  • Rate-theory solvers for irradiation defects.
  • Monte-Carlo workflows for stochastic processes.

How to contribute

Pull requests welcome

Open an issue first for major changes. Every case doubles as an example and a regression test.

Extend without touching the core
  • Add a YAML material card or a Python k(T) / stress callable.
  • Register new physics as a mixin with a distinctive method name.
  • Sphinx docs & UML diagram build in CI.
